# 일회성 HLS 재생

비디오 라이브러리 정렬 행 오른쪽의 **HLS 재생** 텍스트를 누르면 기존
GlassModal 입력창이 열린다. 데스크톱은 모달, 모바일은 같은 디자인의
바텀시트다. 목록이 비었거나 서버 목록을 불러오지 못해도 입력할 수 있다.

HTTP(S) HLS 주소를 받아 기존 비디오 플레이어로 재생한다. `.m3u8` 확장자가
없는 HLS 엔드포인트도 허용하며, 서명된 쿼리 문자열을 변경하지 않는다.
HTTPS Muzio에서는 혼합 콘텐츠가 되지 않도록 HTTPS 스트림만 허용한다.

## 확장에서 호출할 계약

```text
<Muzio origin>/play/hls#url=<URL-encoded stream URL>&title=<optional encoded title>
```

```js
// 재생 후보는 다운로드 화질과 독립적으로 선택한 최대 화질 URL을 사용한다.
const entry = new URL('/play/hls', muzioBaseUrl);
entry.hash = new URLSearchParams({ url: highestQualityUrl, title: pageTitle }).toString();
chrome.tabs.create({ url: entry.href });
```

`url`은 필수, `title`은 선택이다. URLSearchParams로 인코딩해야 원본 URL의
`&`, `+`, `%`, `#`가 보존된다. fragment는 Muzio 서버 요청에 포함되지 않으며,
입력 수신 직후 현재 주소에서도 제거한다. 브라우저가 내비게이션 시점의
주소를 별도로 기록하지 않는다는 보장은 아니다.

유효한 주소는 비디오 화면에서 임시 재생을 시작한다. 주소가 없거나 잘못되면
수정 가능한 입력창을 연다. 확장 프로그램의 설정·재생 대상 선택 UI 변경은
이 저장소의 수신 계약과 별도이며, 이 작업은 확장 저장소를 수정하지 않는다.
OS 앱 링크나 커스텀 URL scheme이 아닌 **Muzio 웹 URL 진입점**이다.

## 재생과 저장

- 임시 소스는 라이브러리, 재생 이력, 이어보기 진행률, 좋아요, 음악 큐에
  추가하지 않는다. 새로고침하면 플레이어는 자동 복원하지 않지만, 아래 공유 목록에서 다시 열 수 있다.
- 파일 최적화·서버 fallback·MP4 인덱스 캐시 요청을 만들지 않는다.
- HLS 목록에 따라 라이브/VOD를 판별한다. 라이브 UI는 기존 Vidstack의 Live
  컨트롤을 사용한다. 네트워크 복구는 기존 HLS provider를 따르며, 치명적
  오류에는 **다시 연결**을 제공한다. 다시 연결은 라이브 현재 지점/VOD
  시작부터 재시도하며, 서명 쿼리 대신 fragment만 바꿔 provider를 재로드한다.
- 자동 재생이 차단되면 **재생**으로 사용자 입력을 받는다.
- 서버가 원본 HLS 목록·조각·키를 받아 같은 origin의 재생 주소로 제공한다.
  브라우저 인증 쿠키·Referer를 전달하거나 DRM을 해제하지 않는다. 서버에서
  접근할 수 없는 원본은 재생되지 않는다. 만료된 주소는 다시 입력해야 한다.

## 플랫폼 전달

웹과 Android는 공통 웹 플레이어를 사용한다. Apple(iOS/iPadOS/macOS)도
일회성 HLS만 웹 플레이어를 사용하며, 라이브러리 영상은 기존 네이티브
플레이어로 돌아간다. 기존 Apple의 서버 영상 경로 허용 정책은 그대로다.
네이티브 브리지 명령/권한은 추가하지 않았다.

Android는 다음 APK 패키징 시 Gradle이 현재 웹 자산을 포함한다. Apple은
연결된 서버의 웹 UI 배포 후 반영된다. 웹 검사 통과는 APK 설치나 Apple
실기기 재생 확인을 대신하지 않는다.

## HLS별 서버 보관과 되감기

영상·오디오 조각과 AES-128 키는 브라우저 IndexedDB 대신 서버의
`os.UserCacheDir()/muzio/hls-server-v1/instance-*/<stream>/`에 저장한다.
재생 목록과 세션 상태는 서버 메모리에만 유지한다. 라이브러리 파일이 아니다.
브라우저에는 디코딩용 짧은 버퍼만 남기며, 과거 구간은 서버에서 다시 받는다.

- **저장 시간 제한 없음. HLS 주소별 1.5GiB**의 미디어 바이트 한도를 적용한다.
  A/B 탭에서 같은 HLS를 시청하면 녹화기·디렉터리·보관분을 공유한다.
  같은 조각을 중복 다운로드/저장하지 않는다. 다른 HLS의 용량과 삭제는 독립적이다.
- 원본 HTTP(S) 주소 전체로 구분한다. fragment는 제외하고 서명 쿼리는 보존한다.
  서명이나 화질 주소가 다르면 별도 HLS다. 마스터 주소에서 선택한 여러 화질·
  오디오 트랙은 그 HLS의 1.5GiB 한도를 함께 사용한다.
- 용량 초과 시 오래된 조각부터 제거하고 키·초기화 조각을 우선 보존한다.
  메타데이터·파일시스템 오버헤드는 별도다. 확보한 연속 구간을 탐색하고
  LIVE로 현재 지점에 복귀한다. 시청 전에 사라진 구간은 복구할 수 없다.
- 방송 종료(ENDLIST) 후에도 목록과 저장분을 보관한다. 원본이 사라져도
  저장된 부분을 다시 재생한다. VOD는 요청된 조각만 보관하므로 미수집 구간은
  원본이 사라지면 재생할 수 없다.
- 개별 조각 32MiB, 원본 목록 1MiB 한도다. DRM/SAMPLE-AES, 델타 전용 목록,
  변수 치환 목록 등 지원하지 않는 스트림은 오류를 표시한다. HLS.js와
  네이티브 HLS가 같은 서버 목록을 사용하며 코덱 지원은 기존 플레이어를 따른다.

임시 HLS 목록 왼쪽에는 재생 영상에서 추출한 192×108 JPEG 썸네일을 표시한다.
같은 HLS의 시청자끼리 한 장을 공유하며 최대 1분 간격으로 갱신한다. 서버에는
64KiB 이하 이미지 한 장만 임시 보관하고, HLS 세션 삭제 시 함께 해제한다.
썸네일 읽기·업로드는 시청 유효 시간을 갱신하지 않는다. 아직 프레임이 없거나
브라우저가 캡처를 허용하지 않으면 영상 아이콘을 표시한다.

## 시청 신호와 20분 유예

- 실제 플레이어의 재생 목록·영상 조각 GET 요청을 시청 신호로 취급한다.
  일시정지나 충분한 버퍼로 요청이 없는 경우도 유지하도록, 현재 활성
  임시 영상은 **1분마다 보조 heartbeat**를 보낸다. 일시정지/종료 화면도 포함한다.
- 같은 HLS를 시청하는 어느 탭·앱의 신호든 공통 유효 시간을 갱신한다.
  페이지의 HLS 목록 조회와 서버 자체의 원본 수집 요청은 갱신하지 않는다.
- **마지막 시청 신호 후 20분까지 수집과 보관을 계속한다.** 탭을 닫거나
  다른 영상으로 바꾸거나 Muzio를 나가도 즉시 녹화를 끝내지 않는다.
  모든 시청 신호가 20분 이상 끊겨야 해당 HLS의 녹화와 캐시를 정리한다.
  한 탭이 떠나도 다른 탭이 시청 중이면 유지된다.
- 유예 안에 같은 HLS를 다시 열거나 목록에서 진입하면 기존 저장분에 연결하고
  유효 시간을 갱신한다. 유예가 지나 이미 삭제됐다면 새로운 세션을 만든다.
- 이 20분은 **시청 부재 유예**이며 저장된 영상의 나이 제한이 아니다.
  시청 신호가 계속 오는 동안에는 20분보다 오래된 영상도 용량 범위 내에서 남는다.
  절전/네트워크 단절로 모든 시청 신호가 20분 넘게 중단되면 열린 화면도
  보관분을 잃을 수 있다. 서버가 실행 중이어야 수집·정리가 가능하다.
- 방송 상태를 확인하지 못한 20분은 수집을 중지하는 기존 규칙을 유지한다.
  시청 신호가 오는 한 이미 저장한 부분은 남긴다. 방송 종료도 캐시 삭제 신호가 아니다.
- 서버 재시작 후 세션 복원은 지원하지 않는다. 오래된 인스턴스 lease가
  20분을 넘으면 다시 실행된 서버가 잔여 디렉터리를 청소한다. 정상 실행 중인
  다른 서버 인스턴스의 디렉터리는 건드리지 않는다.
- 이전 브라우저 DVR 잔여 데이터는 실행 중 매분 검사해 5분 이상 생존 신호가
  없는 이전 세션만 정리한다. 새 재생은 IndexedDB에 쓰지 않는다.

## 공유 목록과 API

`POST /api/hls-sessions`의 `register`는 주소로 기존 녹화에 참여하거나 생성하고,
`heartbeat`는 응답받은 ID의 시청 유효 시간을 갱신한다. 탭별 소유권/종료 API는 없다.
`GET/HEAD /api/hls-cache/<random capability>/<resource>`로 보관분을 읽는다.
API 응답은 브라우저·서비스워커의 영구 캐시에 저장하지 않는다.

목록의 상태 행에는 현재 보관 용량과 1.5GB 한도를 표시한다. 각 행의 삭제 버튼은
`POST action=delete`로 해당 공유 HLS의 수집·저장분·썸네일을 즉시 제거한다.
다른 탭이 같은 HLS를 시청 중이어도 삭제가 적용된다. 다른 HLS는 건드리지 않는다.
삭제 실패 시 항목과 오류를 남겨 재시도할 수 있다. 기존 heartbeat로 삭제된
세션이 재생성되지는 않으며, 다시 재생할 때 새 세션을 만든다.

목록에는 서버가 추적 중인 세션만 보인다. 재시작 전 잔여 디렉터리는 목록에
표시되지 않고, 오래된 인스턴스 lease 기준으로 서버가 자동 정리한다. 현재
인스턴스의 등록 실패 등으로 생긴 세션 없는 디렉터리도 30초마다 검사·정리한다.
서버가 꺼져 있는 동안은 청소하지 않으며, 권한·디스크 오류가 있으면 삭제가
실패할 수 있다. 이 경우 다음 청소 주기에 재시도한다.

- 오른쪽 영상 목록 상단과 Video 라이브러리에서 살아 있는 공유 세션에 진입한다.
  방송이 끝난 저장분도 유효 시간 동안 `방송 종료 · 보관 중`으로 표시한다.
  같은 세션을 이미 보고 있으면 플레이어만 열고, 다른 화면/탭이면 같은 저장분에 참여한다.
- 원본 서명 주소와 재생 주소는 기존 Muzio 서버에 연결된 클라이언트에 공유된다.
  공개 HTTP(S) 원본만 지원하고 사설/LAN 주소는 차단한다. 서버에 최대 256개의
  서로 다른 HLS를 허용한다. 총 저장 공간은 HLS 수에 비례한다.

웹과 앱은 같은 API/화면을 사용한다. 서버 변경과 웹 자산을 함께 배포해야 한다.
Android는 다음 APK 패키징에 웹 자산이 포함되고 Apple은 서버 웹 UI를 사용한다.
실기기와 장시간 실방송 검증은 자동 테스트와 별도다.

상태 행 끝의 `HH:mm`은 마지막 시청 신호(재생 GET 또는 heartbeat) 시각이다.
목록 조회 시각이 아니며, 마우스를 올리면 날짜·초를 포함한 설명을 표시한다.
